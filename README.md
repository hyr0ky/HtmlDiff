Saas 文档差异分析工具 

一个专注于分析 Saas系统（如GitLab ）官方权限文档 (roles and permissions) 历史版本差异的轻量级工具。通过对比不同时间点的文档快照，自动识别新增功能、API 接口及权限变更，为安全研究员提供精准的漏洞挖掘方向。

核心理念

Saas 版本迭代中，新增的功能点、开放的 API 接口和调整的权限模型是未经验证的安全漏洞的高发区。本工具通过自动化对比官方文档，高效地定位这些变更，将传统的“漫无目的”的黑盒测试转化为“有的放矢”的定向分析，极大提升漏洞挖掘效率。

使用方法

1.  获取文档快照：
    手动或使用爬虫脚本定期从 https://docs.gitlab.com/ee/user/permissions.html 抓取 roles and permissions 页面的 HTML 源码，并按照日期命名保存（如 permissions-2025-01-26.html）。

2.  执行差异分析：
    使用 Diff 工具（https://hyr0ky.github.io/HtmlDiff/）对比两个不同日期的文档快照。
   <img width="1534" height="992" alt="图片" src="https://github.com/user-attachments/assets/aa37f336-6e20-43c8-bdad-b6dd0f18b067" />


3.  分析差异结果：
    工具的核心在于解读 Diff 结果。请重点关注以下模式的变更：
    ◦   新增的表格行（+ ）：通常代表一个新功能或一个新API的权限开放。
    ◦   权限单元格的勾选（✓）变化：例如，某个功能从仅 Maintainer 可用变为 Developer 也可用，这可能引入垂直越权。
    ◦   功能描述文字的修改：可能隐含了流程、约束条件的变化。

挖掘指南：如何从差异中寻找漏洞

对比分析后，发现的每一个变更都是一个潜在的挖掘点。请参照以下思路进行测试：

变更类型 发现示例 挖掘思路

新增功能 Import issues from a CSV file 1. 权限校验：低权限用户（如 Reporter）是否也能访问此功能？<br>2. 输入验证：CSV 文件内容是否存在 SQLi、XSS、命令注入？<br>3. 业务逻辑：能否导入恶意数据导致后续漏洞？

权限提升 Manage Feature Flags 权限对 Developer 开放 垂直越权：以 Developer 身份尝试执行原需 Maintainer 权限的操作，检查服务端是否仅依赖前端校验。

新增API接口 文档中新增一个API端点描述 未授权访问：不提供 Token 或 Cookie 直接访问。<br>权限绕过：以低权限用户身份尝试调用。<br>参数污染：测试所有参数是否存在漏洞。

实战案例：
通过对比 2024-12-26 和 2025-01-26 的文档，发现：
•   变更：Export issues to a CSV file 功能的权限从 Reporter 及以上 变更为 Developer 及以上。

•   分析：这是一个明显的权限调整。

•   测试：立即使用 Reporter 权限的用户账号尝试访问该导出功能。

•   结果：如果服务端未同步更新权限校验逻辑，则可能存在 权限绕过漏洞，导致 Reporter 用户仍可导出 CSV。

最佳实践

•   定时抓取：建议在 GitLab 月度版本发布（通常是每月 22 日）后立即抓取一份新文档进行对比。

•   版本归档：妥善保存历史文档快照，建立你自己的文档版本库，以便回溯和追踪变化。

•   结合环境：在本地或测试环境搭建对应版本的 GitLab，对发现的可疑变更点进行实地验证。

•   关注细节：注意文档中看似微小的变化，例如一个复选框（✓）的出现或消失，往往意味着重大调整。
